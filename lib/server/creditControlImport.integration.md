# Worker 03 — integração NC/NE
A prévia permanece POST /api/controle-credito/importacao com bytes originais e x-credit-document-kind nc/ne; GET legado continua retornando member. O resultado NE mantém os campos do parser existente e acrescenta number (seis dígitos), issueDate ISO, netCents, requiresReview e warnings.

## Confirmação (Worker 04 / 06)
- NC HTML: POST /notas-credito JSON {source:"html",draft:{fileBase64,piCorrections?},allocations,deadline,description,expectedRevision?}. fileBase64 = base64 padrão dos bytes originais, sem prefixo data:. Manter o File no cliente até confirmação; não armazenar em localStorage. piCorrections opcional [{sequence,row,pi}], índice zero-based da linha de destino, somente quando PI ausente. O servidor reinterpreta o arquivo e ignora valores/identidade da prévia enviada pelo cliente.
- NC manual: mesmo POST com source:"manual" e draft contendo number,fullNumber,issuingUg,issueDate,description,deadline,operation:"DESCENTRALIZACAO",decentralization:"PROVISAO",documentTotalCents,sequences:[{sequence,origin,destination}]. Cada célula contém item,num,esfera,ptres,fonte,nd,ugr,pi,cents; UG vem da sessão. totalCents é calculado das células; origem e destino precisam coincidir. sourceSystem é MANUAL. Não inventar célula de origem; usuário informa os dados do documento.
- PATCH /notas-credito: id,expectedRevision e alterações de allocations/deadline/description; acknowledgeDeficit quando aplicável.
- NE: POST /notas-empenho JSON {draft:{fileBase64,budget?},creditId,centerId,cellId,acknowledgeDeficit?,expectedCreditRevision?}. budget opcional {nd,ptres,fonte,ugr,pi}, somente para campos ausentes ou inválidos do PDF; não substitui dados válidos. UI confirma vínculo selecionado, inclusive quando referência NC sugerida é diferente ou ausente. O store deve verificar igualdade das dimensões orçamentárias com a célula selecionada, unicidade e saldo em transação; a seleção não é automática. Não criar NE a partir de reforço/anulação nem de PDF com valores divergentes.
- GET NC/NE com id: store devolve projeção autorizada. Não filtrar dados financeiros no navegador.
- Limites originais: HTML 1 MB e PDF 10 MiB; confirmação JSON limitada ao tamanho base64 correspondente mais 128 KiB. Arquivos não são persistidos pela API. Usar IDs das entidades devolvidas para upload posterior via Worker 05; falha de Drive não reverte fatos financeiros.
- Sem dependências, credenciais, cobrança ou mudanças no parser de empenhos compartilhado. A inspeção bounded de streams antes do parser PDF duplica a descompressão de forma deliberada para impedir expansão sem limite no parser legado. Formatos PDF não reconhecidos, ajustes, múltiplos resumos detectados e ambiguidades monetárias são rejeitados para conciliação; validar variantes reais desidentificadas na homologação.
